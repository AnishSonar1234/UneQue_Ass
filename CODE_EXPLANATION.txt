1. OVERVIEW & END-TO-END DATA FLOW
===============================================================================

This project is a real-time lead ingestion system designed to capture Meta
(Facebook/Instagram) Lead Ads submissions, process and verify them on a Node.js
backend, persist them, and push them instantly over WebSockets to a web/mobile
React Native dashboard.

SYSTEM ARCHITECTURE DIAGRAM:

  [ Meta Lead Ad Form ]
           │ (User submits form on FB/IG)
           ▼
  [ Meta Webhook Event ] ────────► HTTP POST /webhook (Header: x-hub-signature-256)
                                         │
                                         ▼
                             [ Backend: verifySignature() ]
                                         │ (Validates HMAC SHA-256)
                                         ▼
                             [ Backend: processLeadgenEvent() ]
                                         │ (Deduplication Check)
                                         ▼
                             [ Backend: fetchLeadFromGraph() ]
                                         │ (Calls Graph API with exponential retries)
                                         ▼
                             [ Backend: addLead() ]
                                         │ (Saves to Memory + JSONL log)
                                         ▼
                             [ Backend: broadcastLead() ]
                                         │ (Sends payload over WSS /ws)
                                         ▼
                             [ Frontend: useLeadsSocket() ]
                                         │ (Receives message, updates state)
                                         ▼
                             [ Frontend UI: LeadRow Component ]
                                           (Animates card highlight & timestamp)

2. BACKEND ARCHITECTURE & FUNCTION-BY-FUNCTION EXPLANATION
===============================================================================

-------------------------------------------------------------------------------
FILE: backend/src/config.ts
-------------------------------------------------------------------------------
PURPOSE: Loads environment variables using `dotenv` and enforces required
configuration variables for server startup.

FUNCTIONS & CONSTANTS:
- `required(key: string): string`
  * Checks if process.env[key] exists.
  * Throws an explicit Error if the key is missing to prevent silent failures.
  * Returns the validated environment variable string.

- `config` (Exported Constant Object):
  * `port`: Server HTTP port (default 3000).
  * `verifyToken`: Meta webhook verification token (`VERIFY_TOKEN`).
  * `appSecret`: Meta app secret key for HMAC validation (`APP_SECRET`).
  * `pageAccessToken`: Facebook Page access token (`PAGE_ACCESS_TOKEN`).
  * `graphVersion`: Graph API version string (default `v21.0`).
  * `nodeEnv`: Node environment (`development` or `production`).
  * `isProduction`: Boolean flag (`nodeEnv === "production"`).


-------------------------------------------------------------------------------
FILE: backend/src/store.ts
-------------------------------------------------------------------------------
PURPOSE: High-performance data access layer providing in-memory storage,
fast deduplication lookup, and append-only file logging (`leads.jsonl`).

FUNCTIONS:
- `initStore(): Promise<void>`
  * Asynchronously initializes the data store.
  * Creates the `leads.jsonl` log file if it does not exist.
  * Reads existing lines from `leads.jsonl` using readline streams.
  * Populates the in-memory array `leads` and tracks IDs in `knownIds` Set
    to ensure persistent state recovery across server restarts.

- `addLead(lead: Lead): void`
  * Appends a newly created Lead object to the front of the `leads` array.
  * Adds `lead.id` to the `knownIds` Set.
  * Asynchronously appends the single JSON-stringified lead line to `leads.jsonl`.

- `haslead(id: string): boolean`
  * Performs O(1) lookup in `knownIds` Set to check if a leadgen ID has already
    been processed, preventing duplicate processing.

- `getLeads(since?: string): Lead[]`
  * Returns array of stored leads.
  * If `since` ISO timestamp string is passed, filters and returns leads newer
    than `since`.

- `closeStore(): void`
  * Flushes and safely closes file streams on graceful server shutdown.


-------------------------------------------------------------------------------
FILE: backend/src/graph.ts
-------------------------------------------------------------------------------
PURPOSE: HTTP client for fetching full lead details (customer name, email, phone)
from Meta's Graph API.

FUNCTIONS:
- `sleep(ms: number): Promise<void>`
  * Helper returning a Promise that resolves after specified milliseconds.

- `fetchLeadFromGraph(leadgenId, pageId, formId, rawCreatedTime): Promise<Lead>`
  * Constructs the Meta Graph API URL:
    `https://graph.facebook.com/v21.0/{leadgenId}?access_token={token}`
  * Executes fetch call wrapped in a 3-attempt loop with exponential backoff
    delay (1s, 2s).
  * Parses response JSON containing `field_data` array.
  * Maps dynamic key-value pairs (full_name, email, phone_number, etc.) into
    a normalized `fields` map.
  * On success, returns structured `Lead` object with `status: "ok"`.
  * If all 3 retries fail, logs error and returns a degraded fallback `Lead`
    object with `status: "fetch_failed"`.


-------------------------------------------------------------------------------
FILE: backend/src/webhook.ts
-------------------------------------------------------------------------------
PURPOSE: Handles HTTP endpoints for Meta Webhook subscription verification
and incoming webhook event processing.

FUNCTIONS:
- `verifySignature(req, res, next)` (Express Middleware):
  * Reads `x-hub-signature-256` header from incoming HTTP POST request.
  * Computes expected HMAC SHA-256 digest of raw request buffer using `config.appSecret`.
  * Compares digests using `crypto.timingSafeEqual()` to prevent timing attacks.
  * If valid, calls `next()`. If invalid, returns HTTP 401 Unauthorized.

- `processLeadgenEvent(leadgenId, formId, pageId, createdTime, adId, adgroupId): Promise<void>`
  * Core processing pipeline shared by webhook handler and dev simulator.
  * Step 1: Checks `haslead(leadgenId)`. If duplicate, exits immediately.
  * Step 2: Calls `fetchLeadFromGraph()` to retrieve customer fields.
  * Step 3: Overwrites optional `adId` or `adgroupId` if provided in payload.
  * Step 4: Calls `addLead(lead)` to persist the lead.
  * Step 5: Calls `broadcastLead(lead)` to push live lead to all WebSocket clients.

- `createWebhookRouter(): Router`
  * Express Router factory mounting two routes:
    1. `GET /webhook`: Meta hub verification handler. Compares `hub.verify_token`
       with `config.verifyToken` and echoes `hub.challenge` on success.
    2. `POST /webhook`: Webhook payload dispatcher. Parses `entry` and `changes`
       arrays for `field === "leadgen"` and invokes `processLeadgenEvent()`.


-------------------------------------------------------------------------------
FILE: backend/src/ws.ts
-------------------------------------------------------------------------------
PURPOSE: Manages active WebSocket connections and broadcasts real-time updates.

FUNCTIONS:
- `createWss(server: http.Server)`
  * Instantiates a `WebSocketServer` attached to the HTTP server on path `/ws`.
  * Manages connection events, sets up 30-second ping/pong heartbeat intervals
    to detect broken client connections, and cleans up terminated sockets.

- `broadcastLead(lead: Lead): void`
  * Serializes lead object to JSON message format: `{ type: "lead", data: lead }`.
  * Iterates over all active clients in `wss.clients` and sends string payload
    to every socket in `readyState === WebSocket.OPEN`.

- `getClientCount(): number`
  * Returns active connected WebSocket client count (used by `/health` endpoint).


-------------------------------------------------------------------------------
FILE: backend/src/server.ts
-------------------------------------------------------------------------------
PURPOSE: Main entry point bootstrapping the application server.

FUNCTIONS:
- `bootstrap(): Promise<void>`
  * Step 1: Awaits `initStore()` to initialize file/memory persistence.
  * Step 2: Configures Express application instance & CORS middleware.
  * Step 3: Configures raw body parser specifically for `POST /webhook`.
  * Step 4: Mounts API routes:
    - `GET  /health` -> Returns system health & client count.
    - `GET  /leads` -> Returns list of leads (supports `?since=` query).
    - `POST /dev/simulate` -> Injects fake test lead (development mode).
  * Step 5: Creates HTTP server and attaches WebSocket server via `createWss()`.
  * Step 6: Listens on `config.port` and handles graceful shutdown signals (SIGTERM/SIGINT).

3. FRONTEND ARCHITECTURE & FUNCTION-BY-FUNCTION EXPLANATION
===============================================================================

-------------------------------------------------------------------------------
FILE: mobile/config.ts
-------------------------------------------------------------------------------
PURPOSE: Dynamic environment and URL resolution.

FUNCTIONS:
- `getApiUrl(): string`
  * Returns `process.env.EXPO_PUBLIC_API_URL` if defined.
  * On web, checks `window.location.origin`: returns `http://localhost:3000` if on
    localhost/127.0.0.1, or `window.location.origin` if deployed in production.

- `getWsUrl(): string`
  * Returns `process.env.EXPO_PUBLIC_WS_URL` if defined.
  * On web, auto-detects protocol (`wss:` for HTTPS, `ws:` for HTTP) and returns
    `${protocol}//${host}/ws`.


-------------------------------------------------------------------------------
FILE: mobile/useLeadsSocket.ts
-------------------------------------------------------------------------------
PURPOSE: React hook managing real-time WebSocket connection lifecycle, exponential
reconnect backoff, and lead state updates.

FUNCTIONS:
- `clampList(leads: Lead[]): Lead[]`
  * Restricts in-memory leads array to `config.MAX_LIST_SIZE` (200 items).

- `useLeadsSocket(): UseLeadsSocketResult`
  * Main custom hook returning `{ leads, newLeadIds, connectionStatus }`.
  * Internal functions:
    - `fetchLeads(since?: string)`: Makes REST HTTP GET request to `/leads` to fetch
      initial or catch-up lead records.
    - `addNewLead(lead: Lead)`: Inserts lead at head of array, adds `lead.id` to
      `newLeadIds` set, and sets a 2-second timeout to clear the highlight set.
    - `connect()`: Opens new `WebSocket` socket connection to `config.WS_URL`.
      * `onopen`: Sets status to `"live"`, resets reconnect delay, and executes
        catch-up `fetchLeads(since)`.
      * `onmessage`: Parses WS payload and calls `addNewLead()`.
      * `onclose` / `onerror`: Updates status to `"offline"` and invokes `scheduleReconnect()`.
    - `scheduleReconnect()`: Implements exponential backoff strategy (`1s`, `2s`, `4s`, ..., `30s`)
      using `setTimeout` to safely reconnect without flooding the server.


-------------------------------------------------------------------------------
FILE: mobile/LeadRow.tsx
-------------------------------------------------------------------------------
PURPOSE: Memoized lead card component with highlight animations.

FUNCTIONS:
- `formatRelativeTime(isoString: string): string`
  * Computes millisecond difference between `Date.now()` and lead `receivedAt` timestamp.
  * Formats into human-readable relative string (`12s ago`, `5m ago`, `2h ago`, `1d ago`).

- `LeadRow` (Memoized Component):
  * Maintains an `Animated.Value` ref `highlight`.
  * When `isNew === true`, triggers `Animated.timing` over 1800ms interpolating card
    background color from dark highlight `#1e3a5f` back to standard card background `#1a1a2e`.
  * Renders customer name, email icon, phone icon, custom field key-values, and form ID.


-------------------------------------------------------------------------------
FILE: mobile/App.tsx
-------------------------------------------------------------------------------
PURPOSE: Root application view component.

FUNCTIONS:
- `App()` (Exported Default Function):
  * Invokes `useLeadsSocket()` hook.
  * Renders header with application title and live connection status badge
    (● Live / ◌ Reconnecting / ✕ Offline).
  * Renders virtualized `FlatList` component with `LeadRow` items, `ListEmptyComponent`
    (waiting state), and `ListHeaderComponent` (lead count).

4. STEP-BY-STEP EXECUTION FLOW (INCOMING LEAD TRACE)
===============================================================================

Let's trace exact code execution step-by-step when a lead is submitted:

[STEP 1]: Meta sends HTTP POST request to `https://your-domain.com/webhook`
          Payload includes `x-hub-signature-256` header and JSON body.

[STEP 2]: Express receives request in `backend/src/server.ts`.
          `express.raw()` captures raw buffer for signature validation.

[STEP 3]: `verifySignature()` middleware in `backend/src/webhook.ts` executes.
          Computes HMAC SHA-256 hash of body using `config.appSecret`.
          Validates hash equality. Passes control to route handler.

[STEP 4]: Route handler iterates over `entry[].changes[]`.
          Finds change with `field === "leadgen"`.
          Extracts `leadgen_id`, `form_id`, `page_id`, `created_time`.

[STEP 5]: Calls `processLeadgenEvent()` in `backend/src/webhook.ts`.
          Evaluates `haslead(leadgen_id)`. If false, proceeds.

[STEP 6]: Calls `fetchLeadFromGraph()` in `backend/src/graph.ts`.
          Sends GET request to Meta Graph API.
          Parses response `field_data` array into `fields` map.
          Returns normalized `Lead` object.

[STEP 7]: Calls `addLead(lead)` in `backend/src/store.ts`.
          Adds lead to in-memory array and appends JSON line to `leads.jsonl`.

[STEP 8]: Calls `broadcastLead(lead)` in `backend/src/ws.ts`.
          Serializes lead object to `{ type: "lead", data: lead }`.
          Sends WS frame to all open client sockets.

[STEP 9]: `ws.onmessage` fires inside `useLeadsSocket.ts` on web dashboard client.
          Parses JSON payload and identifies `type === "lead"`.
          Calls `addNewLead(msg.data)`.

[STEP 10]: `addNewLead()` updates `leads` state (prepends lead) and adds `lead.id`
           to `newLeadIds` state set.

[STEP 11]: React re-renders `FlatList` in `App.tsx`.
           `LeadRow` receives `isNew={true}`.

[STEP 12]: `LeadRow` `useEffect` triggers 1.8-second `Animated.timing` background
           interpolation animation. User sees card glow blue and fade smoothly!
